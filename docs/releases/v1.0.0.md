# Postrail v1.0.0

**AI drafts. You decide what ships.**

**First source release · September 8, 2026 · MIT license**

Postrail is a self-hosted workflow for preparing LinkedIn content, reviewing it in Telegram, requesting focused revisions, and publishing the current version only after explicit human approval. This source release brings the application, offline acceptance flow, integration adapters, tests, and documentation into one package.

## A review loop you can inspect

The central interaction is intentionally small:

1. A scheduled job selects an idea and creates a reviewed draft.
2. Telegram receives the draft and its actions.
3. The operator asks for an edit, such as a shorter opening or no CTA.
4. The application preserves untargeted paragraphs and saves a new version.
5. Explicit approval authorizes that current version for publication.
6. The publication result is stored and sent back to the operator.

The LLM has no approval or publication method. Draft versions, approval records, jobs, and publication attempts are persisted. Old approvals cannot silently authorize revised text. A provider response whose publication outcome is uncertain is routed to reconciliation rather than an automatic second POST.

## Included in this version

**Content planning and drafting.** A configurable idea backlog, balanced content pillars, recent-topic and format penalties, structured model responses, separate writer and critic calls, bounded retries, and deterministic content checks. The current editorial configuration is Turkish-first, with business-oriented web, AI, automation, and SaaS topics.

**Natural-language revisions.** Common Turkish editing requests resolve to a set of paragraph IDs before the model edits. Requests for the opening or CTA can preserve all other text exactly. Ambiguous references ask for clarification. Accepted revisions create another version and require another human approval.

**Telegram and LinkedIn integrations.** A private-chat operator allowlist, inline actions, cancellation and postponement, OAuth support, and the official LinkedIn publication adapter. Account-specific product access and scopes must be configured by the operator.

**Learning from available measurements.** Optional permission-dependent post analytics, manual measurement entry, and weekly reports. Sufficiently observed patterns can influence topic, format, opening type, length, and CTA suggestions, while exploration remains part of the policy. Missing metrics stay missing; the weighted comparison score is a project heuristic, not a growth guarantee.

**Durable operations.** PostgreSQL migrations, persistent work queues and notifications, deduplication, structured logs, environment setup checks, administration APIs, Docker/Compose configuration, and an optional n8n orchestration workflow.

**A reproducible local presentation.** Forty distinct offline content fixtures and a runnable acceptance flow. The hero, project-card, workflow, and animated demo assets present recorded fixture data; they are not screenshots of a shipped dashboard or evidence of a live LinkedIn account result.

## Try the local workflow

With Node.js 24+ and npm, from the repository directory:

```sh
npm ci
npm run check
npm run demo
```

This path uses explicit offline adapters. It needs no OpenAI, Telegram, or LinkedIn credentials and publishes nothing to a real account. The default test command may skip dedicated native PostgreSQL cases unless a test database is supplied; `npm run test:postgres` requires that database and fails clearly if its connection is absent.

For a real installation, follow the [README](../../README.md) and [activation guide](../ACTIVATION.md). Connecting credentials does not approve a post. Read the final Telegram draft and approve it only when you want that version published.

## Known limits

- Real OpenAI, Telegram, and LinkedIn integrations have not been exercised with live credentials in the recorded development validation. Real model writing quality, cost, and account-specific API permissions remain to be assessed during activation.
- The production Docker image build passed in GitHub CI. Container startup, persistent volumes, public TLS, and optional n8n activation still require verification on the deployment host.
- The application currently supports Turkish content and one configured operator per deployment. It does not include a hosted SaaS dashboard, billing, or self-service multi-account onboarding.
- Offline fixtures are finite. They demonstrate workflow behavior, not the quality of a live AI writing service.
- Source checks combine operator-supplied facts, lexical rules, and model review. They are fallible and do not independently browse and verify the web.
- Default repetition detection is lexical. An embedding interface and an optional Hacker News source adapter are included, but a default vector backend and scheduled trend ingestion are not enabled.
- Publishing recovery does not assume that the LinkedIn provider offers an exactly-once guarantee. Uncertain outcomes require an operator decision based on the actual account state.

The [content-engine guide](../CONTENT_ENGINE.md) describes the implemented policy in detail. The [roadmap](../ROADMAP.md) separates current behavior from contribution directions without promising dates or results.
